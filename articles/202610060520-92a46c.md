月曜に出社したら、ObjectARXと.NET APIの開発環境まとめ記事が同じ著者から4本連続で上がっていた。IJCAD側の整理も含めて4本。社内でCADカスタマイズを細々と続けている立場からすると、こういう横断的な一覧は年に数回しか出てこないので、今週はこの話題を中心に拾っていく。

## 今週のトピック

### AutoCADとIJCADの開発環境、2026年10月時点の棚卸し

tanoue2715氏が同じ日に投稿した4本は、AutoCADとIJCADの両方について、ObjectARX／GRX（C++）とManaged .NET APIの開発環境を年版ごとに整理したもの。地味だが、社内でレガシーLISPやARXアプリを抱えている部署には響く内容だった。

- [現在入手可能なAutoCAD向けObjectARX（C++）開発環境一覧](https://qiita.com/tanoue2715/items/83cda76312c4ebd17b5e)：AutoCAD 2024〜2027を対象に、Visual StudioとPlatform Toolset、SDK、バイナリ互換系列の対応を整理
- [現在入手可能なAutoCAD向け.NET API開発環境一覧](https://qiita.com/tanoue2715/items/625aeea74c6a74c5e34c)：.NET Framework 4.8 → .NET 8 → .NET 10 と世代が3段跳びしている現実を一枚で把握できる
- [現在入手可能なIJCAD向けGRX（C++）開発環境一覧](https://qiita.com/tanoue2715/items/db5fa9f58b190031803f)
- [現在入手可能なIJCAD向け.NET API開発環境一覧](https://qiita.com/tanoue2715/items/e0f430a313cf7838a524)：IJCAD 2026では.NET 8へ移行し、プロジェクト形式・参照方法・名前空間を含めた移行が必要と明記

特に重要なのは、AutoCAD .NET APIが2024〜2027の短い期間で.NET 4.8 → 8 → 10と動いている点。2026年にはAutoCAD 2025系と2026系の両方がアップデートで切り替わると書かれている。社内ツールの保守工数見積もりに直結する話。

### Autodesk「AI Transparency Cards」の拡充

[AI の透明性を高める「AI Transparency Cards」を拡充](https://news.google.com/rss/articles/CBMijAFBVV95cUxNUk1PZVJjTUJ5T2M1V1FXMnpqdHR1czRZbWVhQ2xBaUJXVHdfNnhEWVdNZUVCRXFqSVk1bm1hMUR1ME94eUZqbmZNVks3ZE9obWFBRzBoeEpKbnd4UXJpV2MtTXlKbEV6QzZUZ0h5aVROdl9BdHR0U1RLTUZ0aDFWRDhkcHR5dldPN3N2Sw?oc=5)というAutodeskのニュース。製品内のAI機能について、何のデータでどう動いているかを開示するカードを増やす話。発注者から「設計にAIを使っているなら説明してほしい」と言われ始めた今、こういう公式ドキュメントがあると社内説明資料に組み込みやすい。

### Parallels Desktopの新版でAutoCAD対応を明記

[最新バージョンの Parallels Desktop for Mac](https://www.parallels.com/jp/desktop-upgrade/?x-source=ipn_retail&promo=klv&client_id=71521859.1784267108&session_id=1790755719)のアップグレード案内に、128GB vRAM、32 vCPU、AutoCAD・Bluebeam・ArcGISなどのデータ集約型アプリの実行がうたわれている。意匠の若手にMac派が増えてきた体感もあるので、Mac + Parallels + AutoCADという構成を正式サポート対象として検討する余地はありそう。

## ゼネコンBIM担当としての考察

4本の開発環境記事を見て、まず社内の「2018年頃に書かれた.NET Framework 4.8のARXプラグイン」の棚卸しをやらないとまずい、と感じている。うちだと、鉄骨の継手検討用に書かれた社内ツールが.NET 4.8のまま放置されていて、AutoCAD 2026でそろそろ動かなくなる見込み。.NET 8と.NET 10の分断は、ビルドし直せば済む話で終わらず、参照しているサードパーティDLLの再コンパイル可否まで芋づる式に波及してくる。

社内標準化の観点では、「どの年版のAutoCADで、どのツールが動く／動かない」をマトリクスで管理する運用に切り替えるタイミングだと思ってる。協力会社に図面を回すとき、相手がAutoCAD 2024で止まっていて、こちらの2027で保存したDWGを開くと社内アドインの属性が落ちる、という事故が去年あった。年版だけでなくAPI世代まで含めた互換表を協力会社と共有する必要がある。

IJCADの資料が同時に整理されているのも、現実的にありがたい。発注者がAutoCAD指定でも、協力会社の下請けまで降りるとIJCADが混じっていることは珍しくない。.NETコードを両対応で書く社内ガイドを作るなら、今回のtanoue2715氏の2本をベースに社内版へ焼き直すのが早い。

一方で導入ハードルも正直に書くと、.NET 10対応の開発環境を各担当PCに配るとなると情シスの標準イメージ更新が絡み、半年仕事になる。先に動くのは「現行のツールが2027で動作するかの検証だけ」で、新規開発は様子見というのがうちの現実的な落としどころかもしれない。

## まとめ

派手な新機能リリースはない週だったが、.NET世代の分断とAI説明責任という、裏方のBIM推進担当がじわじわ対応を迫られる話題が揃っていた。来週、情シスとCAD保守の打ち合わせがあるので、.NETランタイム対応表を一枚持ち込むところから始める。4.8のまま放置されたツール群、たぶん10本以上ある。
